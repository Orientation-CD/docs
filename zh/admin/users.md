# 用户管理

用户分区位于 `GET /admin/users`（模板 `app/templates/admin/users.html`），让你搜索已注册的客户账号并调整其权益。你不能在这里创建客户账号——客户通过移动端应用自助注册。

## 搜索

使用搜索栏（`_search.html`，`data-live-search`）。输入时实时匹配：
- 显示名称
- 手机号（E.164）
- 用户 ID
- 企业 / 工作区名称

结果每页 50 条分页（`_pagination.html`）。此页面没有状态筛选器；停用/注销账号在表格中标记。

## 用户表格

| 列 | 显示内容 |
| --- | --- |
| User | 显示名称 + 用户类型徽章（个人 / 企业 / 管理员）。 |
| Phone | 账号的 E.164 手机号。 |
| Jobs | 该用户拥有的设计任务数。 |
| Personal tokens | 当前剩余余额，加上在途任务锁定的"预留"金额。 |
| Type | 账号类型徽章。 |
| Workspaces | 该用户持有的企业成员关系（所有者/成员），加上个人"允许的工作区"配额。 |
| Status | 活跃 / 已停用 / 已注销徽章。 |

每行可展开以显示下文描述的账号操作。

## 操作

### 调整积分（`POST /admin/users/{id}/tokens`）

充值或扣减用户的**个人**积分余额。

| 字段 | 类型 | 必填 | 说明 | 默认值 |
| --- | --- | --- | --- | --- |
| Adjustment | number | 是 | 带符号的积分增减量。范围 −1,000,000,000 … +1,000,000,000。不能为 `0`。 | — |
| Reason | text | 否 | 记录在台账条目中的自由文本备注。 | — |

- 正值为账户入账（`TOKEN_ADJUSTMENT_CREDIT`）；负值为扣账（`TOKEN_ADJUSTMENT_DEDUCTION`）。零值调整会被拒绝。
- 变更会写入持久的 `TokenLedgerEntry`，确保财务和积分明细页面保持一致。

### 允许的工作区数（`POST /admin/users/{id}/allowed-workspaces`）

一个用户可以加入多少个企业工作区。

| 字段 | 类型 | 必填 | 说明 | 默认值 |
| --- | --- | --- | --- | --- |
| Allowed workspaces | number | 是 | **1 到 100** 之间的整数。 | 当前值 |

- 不能将此值设低于用户已加入的工作区数量——服务端会拒绝，以防止所有者被孤立。

### 停用 / 重新激活

在活跃和停用之间切换账号（`account_status` / `is_active`）。被停用的用户无法登录或运行任务，但数据会保留。使用该行的停用/重新激活控件。

### 归档已注销用户（软移除）

根据归档策略，已注销用户会立即被归档。移除操作（`POST /admin/users/{id}/remove`）通过 `remove_user_account` 执行**软归档**：它将用户标记为已移除/已匿名化，而不是删除行，以保留计费和任务历史。

> 从 UI 中移除/归档用户是不可逆的，并且会保留台账记录供财务使用。如果你之后可能恢复访问权限，请优先使用停用。

## 账号生命周期摘要

| 状态 | 含义 |
| --- | --- |
| 活跃 | 可以登录并运行任务。 |
| 已停用 | 登录被阻止；数据保留。 |
| 已注销 / 已匿名化 | 软归档；从客户界面中看起来已被移除，历史保留。 |

## 提示

- 谨慎调整积分并始终记录原因；每次调整都可以在积分台账中审计。
- 使用[工作区](/admin/workspaces)管理企业积分池和成员关系；此页面只操作用户的*个人*余额。
