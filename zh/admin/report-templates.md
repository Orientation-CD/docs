# 报告模板

报告模板页面位于 `GET /admin/report-templates`（模板 `app/templates/admin/report_templates.html`），是客户接收的报告版式的原生 HTML/Jinja 编辑器。这是一个强大、刻意偏技术的工具：你编辑受信源码，预览它，然后保存一个候选版本并提升为线上副本。

## 什么是报告模板

报告模板是生成的设计报告的 HTML/Jinja 包装层。它定义整体框架、章节顺序和样式，同时保留报告引擎数据填充的显式章节块不变。模板有一个**作用域**：

| 作用域 | 含义 |
| --- | --- |
| `global` | 所有人的默认版式。 |
| `enterprise` | 针对某个特定工作区的覆盖。 |

存在哪些作用域通过 `GET /admin/report-templates/scopes` 实时获取（目的地搜索框使用）。

## 编辑器

单页编辑器由 `admin.js`（`data-report-template-editor`）驱动。

| 控件 | 含义 |
| --- | --- |
| Template path (search) | 输入 **Global**、企业名称或企业 ID 来选择目的地作用域。输入后显示匹配项，最多 5 个。 |
| HTML and Jinja source | 大型文本域，包含确切的模板源码。Jinja 文本在保存时逐字保留。 |
| Preview | 使用示例数据渲染模板而不保存。 |
| Save | 校验源码并将候选写入选定目的地。 |

## 背后的端点

| 端点 | 方法 | 作用 |
| --- | --- | --- |
| `/admin/report-templates/scopes` | GET | 搜索可用目的地（Global + 企业）。 |
| `/admin/report-templates/content` | GET | 将某作用域当前生效的模板源码加载到编辑器。 |
| `/admin/report-templates/preview` | POST | 校验 + 渲染预览，返回一个签名 URL 供查看。 |
| `/admin/report-templates/candidate` | POST | 将提交的源码保存为持久候选，然后提升它。 |

## 候选提升生命周期

保存是一个两阶段、受保护的过程，在 UI 中显示为步骤列表：

1. **候选已保存** —— 提交的源码经过校验并写为持久候选（在 `prompt-management`/报告模板咨询锁下）。
2. **生效的 OSS 副本** —— 候选被提升为报告引擎实际使用的线上对象存储副本。

UI 强制执行的规则：
- Preview 和 Save 在未选择作用域且无源码之前**禁用**。
- **待处理候选必须完成提升后才能再次保存**——提升进行中不能开始第二次保存（状态面板显示"Saving / In progress"）。
- 状态面板报告目的地、更新时间、候选路径和每步状态。

## 与报告系统的协作方式

报告生成时，报告引擎加载该报告作用域的**生效**模板（如果有企业覆盖则用企业覆盖，否则用全局），将数据填充的章节块渲染进去，然后提供结果。编辑模板不会重新渲染已接受的历史报告——它只影响提升后生成的报告。

## 警告

- 你正在编辑**原生 HTML/Jinja**。损坏的标记或未闭合的块会在预览时表现为渲染错误——保存前务必预览。
- 保留报告引擎注入的显式章节块；重新排序/重新样式化没问题，删除它们会丢失报告内容。
- 保存即立即提升到生产。使用企业作用域在提升到 Global 之前先在单个工作区上测试新版式。
