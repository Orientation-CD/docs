# 简介

欢迎阅读 **YuanZhu AI**（装易装AI）文档。本指南假设你**零基础**——不了解产品、不了解代码库、也不了解微信小程序开发。读完本节，你会明白这个项目是什么、它由哪些部分组成，以及如何在你自己的机器上跑起来。

## YuanZhu AI 是什么？

YuanZhu AI 是一个**微信小程序**，把**生成式 AI 图像模型**应用到真实的室内设计中。用户拍摄（或录制）一个房间，系统会：

1. 接收照片（外加可选的蒙版/参考图）或客户需求的语音录音，
2. 调度一个异步**设计任务**，
3. 调用**AI 图像提供方**（大型图像生成模型）产出效果图，或把录音转写成结构化的 **markdown 需求总结**，
4. 把结果组装成一份**专业交付物**，供用户查看、回放与分享。

产品面向业主、装修设计师与施工团队。它通过**积分 + 订阅**模式变现（参见
[后端 → 计费与积分](/backend/billing-tokens)）。

## 用户能做什么？

首页由一个首屏轮播加一个功能宫格组成。已发布的功能有：

| 功能 | 作用 |
| --- | --- |
| **室内设计**（室内设计） | 从一张照片出发做整屋重设计 |
| **局部改造**（局部改造） | 改动某个特定区域（墙面、天花板、角落……） |
| **家居试搭**（家居试搭） | 用画布蒙版把家具放到空间照片上 |
| **厨房改造**（厨房改造） | 厨房专用设计流程 |
| **卫生间改造**（卫生间改造） | 卫生间专用设计流程 |
| **彩平图设计**（彩平图设计） | 把平面底图转成彩色平面图 |
| **录音需求总结**（录音需求总结） | 上传/录制 1–3 个音频文件，得到 markdown 总结 |
| **方案汇报**（方案汇报） | 组装一份专业 HTML 报告（目前服务端已门控） |

开发中的占位功能（"一键漫游"、"装修叙事动画"）会出现在首页宫格上，但标注为"即将上线"。

用户还有**工作空间**模型：每个账号都有一个**个人工作空间**，用户也可以加入或创建**企业工作空间**（企业空间），由所有者管理成员、席位、邀请与共享方案。

## 三个仓库

项目位于 `Orientation-CD` GitHub 组织下，拆分为三个仓库：

### 1. 前端——`wechat_mini_program`

一个 **uni-app + Vue 3 + TypeScript + uview-plus** 项目，主目标是
**微信小程序**（也可编译到 H5 与其他小程序平台）。它在
**`ui-integration`** 分支上开发。

核心理念：

- 每个页面都通过**异步仓库层**取数据；页面绝不直接发 HTTP。
- 前端以 **Mock 模式**（不需要后端）或 **API 模式**（通过
  `/api/v1` 与真实后端对话）运行。这在**编译期**通过 Vite 别名与 `VITE_`
  环境变量决定——参见[前端 → 数据源模式](/frontend/data-source-modes)。
- 用户可以以**游客**身份体验所有功能；微信注册/登录门槛在最终提交步骤才触发。
- 首页积分预检与可续播语音回放都内建在功能流程中。

### 2. 后端——`YuanZhu-AI`

一个 **Python 3.12 / FastAPI** 服务，提供 REST API、异步任务管线、计费、认证与报告。它在
**`main`** 分支上开发。

核心理念：

- **REST API**——一切都在 `/api/v1` 下。
- 用 **ARQ** worker 做**异步任务处理**：一个*提交 worker* 与 AI 提供方对话，一个*轮询 worker* 盯守提供方完成情况。
- **PostgreSQL** 通过 **SQLAlchemy 2.0 + Alembic** 持久化状态。
- **Redis** 用于 ARQ 队列、限流、进度指标与缓存。
- **对象存储**（S3 兼容：本地用 MinIO，生产用阿里云 OSS）存放上传的照片、音频、生成的效果图与报告素材。
- **微信集成**用于登录（`code2session` + 手机号），以及用于购买积分包与订阅的**微信支付**（JSAPI）。

### 3. 文档——本仓库（`docs`）

一个 **VitePress** 站点，每次推送到 `main` 都会**自动部署到 GitHub Pages**。你现在正在读的就是它。
