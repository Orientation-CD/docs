# 常见问题

刚上手项目时常被问到的问题。如果这里没有你的问题，试试[术语表](/get-started/glossary)或在文档中搜索。

## 产品与项目

**问：这个产品到底是做什么的？**
答：它是一个微信小程序，把房间的照片（或语音录音）变成 AI 生成的室内设计方案与专业交付物。用户上传照片或录音，后端调度一个 AI"设计任务"，模型渲染出结果（或把录音总结成 markdown），用户再查看与回放。参见[简介](/get-started/introduction)。

**问：为什么要分三个仓库？**
答：前端（`wechat_mini_program`）、后端（`YuanZhu-AI`）与文档（`docs`）。它们的开发与发布节奏相互独立，分仓让每个团队可以各自工作、各自部署。

**问：哪些分支是主分支？**
答：前端 → `ui-integration`；后端与文档 → `main`。动手前务必先同步到最新（参见[快速开始](/get-started/quickstart)）。

**问：微信 AppID 是什么？我可以提交 AppSecret 吗？**
答：AppID 是 `wxec0d577de41255aa`（公开）。**AppSecret 绝不能提交**到前端仓库——它只存在于后端，由后端把登录 `code` 换成 `openid`。

## 运行项目

**问：本地开发需要真实微信凭据吗？**
答：不需要。本地栈自带 mock 微信身份、mock 支付与 mock AI 提供方。只有在测试生产行为（真实微信登录/支付、真实模型调用）时才需要真实凭据。参见[快速开始](/get-started/quickstart)。

**问：我能在完全不跑后端的情况下做 UI 开发吗？**
答：可以——跑 `pnpm dev:mp-weixin:mock`。前端对每个仓库都有完整的内存 mock，并预置了个人 + 组织工作空间。

**问：为什么小程序显示"无法连接后端服务"？**
答：通常是 `VITE_API_BASE_URL` 写错了，或者小程序访问的是非 HTTPS、非回环地址。请用 `api-local` 开发模式（指向 `http://127.0.0.1:8080`），确认后端栈在运行，并在微信开发者工具中开启"不校验合法域名"。

**问：如何让前端指向另一个端口上的后端？**
答：在命令行覆盖环境变量：
`VITE_API_BASE_URL=http://127.0.0.1:9090 pnpm dev:mp-weixin:api-local`。

**问：如何在真机上测试？**
答：把手机与 Mac 放到同一局域网，运行
`pnpm build:mp-weixin:api-device-wechat`，再把
`dist/build/mp-weixin` 导入开发者工具。

## 架构

**问：为什么设计处理是异步的（worker + 轮询）？**
答：AI 图像生成与语音摘要要几十秒到几分钟。让一个 HTTP 请求阻塞这么久既不可用又脆弱。后端改为入队一个任务，worker 对提供方处理它，前端带退避地轮询持久化状态。参见[设计任务](/backend/design-jobs)。

**问：图片和音频存在哪里？**
答：在 S3 兼容对象存储——本地 MinIO，生产阿里云 OSS。前端通过预签名 POST 表单**直接上传到存储**，绝不经过后端代理字节。后端只签发意图并校验完成。参见[素材与对象存储](/backend/assets-storage)。

**问：每个 worker 的职责是什么？**
答：**提交 worker** 调用 AI/语音提供方创建一个提供方任务；**轮询 worker** 反复检查该任务并持久化结果。参见[架构总览](/get-started/architecture)。

**问：为什么首页在打开功能前要检查积分？**
答：这是一道友好的 UX 护栏（#224、#226）：`inspectHomeEntry(tokenCost)` 统计在途任务数（`ACTIVE_JOB_LIMIT = 5`），并把个人积分余额与任务的目录成本比较。任一不满足，用户会被送去商店或"我的方案"。后端在提交时仍会原子地执行同样的限制。

**问：语音播放是怎么续播的？**
答：markdown 总结页维护一个按素材索引的 `playbackByAsset` 映射
（`status`、`currentTime`、`duration`）。暂停或切换录音时把当前位置写回，新的 `InnerAudioContext` 以
`context.startTime = resumeAt` 启动。已播完的录音则从 0 重新开始。

## 计费与账户

**问：积分经济是怎么运作的？**
答：新用户可能收到一笔赠送积分。每个设计任务提交时预留积分，完成时按实际成本结算。用户通过微信支付购买积分包或订阅来充值。参见[计费与积分](/backend/billing-tokens)。

**问：用户用功能前必须登录吗？**
答：不用。所有图像功能都能以**游客**身份体验；微信注册/登录门槛在最终提交步骤才触发。

**问：为什么不能续订一个生效中的订阅？**
答：本版本刻意不支持提前续订。"权益管理"页会显示提示（"暂不支持提前续订"）并给出套餐到期日期；用户在到期后再购买。没有自动扣费。

**问：个人工作空间和企业工作空间有什么区别？**
答：个人工作空间是私有的。企业工作空间是共享的：所有者管理席位、邀请与成员；成员看到共享方案。角色只有 owner 与 member——没有成员角色调整。参见[工作空间与组织](/backend/workspaces-orgs)。

## 调试与贡献

**问：怎么跑测试？**
答：`pnpm test:domain`（纯逻辑，毫秒级）、`pnpm test:unit`
（Vitest），以及 `pnpm quality:mp-weixin:mock` 跑完整本地门禁。参见
[测试与质量门禁](/frontend/testing)。

**问：为什么构建在"包体积过大"上失败了？**
答：质量门禁强制每个分块 ≤ 1.5 MiB、每个内置媒体 ≤ 200 KiB。重代码必须放进分包；大图应放在
`VITE_ASSET_BASE_URL` 背后的 CDN 上。

**问：为什么我新加的响应字段被忽略/拒绝了？**
答：每个后端响应都由一个规整化函数校验，遇到意外形态就抛
`*RESPONSE_INVALID`。把该字段加进对应的 `map*` 函数及其单元测试，并运行 `pnpm check:api-contract`。

**问：怎么编辑这些文档？**
答：所有内容都是 `docs/` 下的 Markdown。编辑一个文件、push，VitePress
站点会自动重建。本地预览：

```bash
cd docs
pnpm install
pnpm docs:dev
```

然后打开打印出的本地 URL。

**问：文档有写作规范吗？**
答：保持**零基础友好**（文档假设零背景），使用真实的文件/端点/环境变量名，并且每当你描述一个 API 时，带上完整调用链（参见[参考](/reference/rest-api)）。内部链接使用形如 `/frontend/architecture` 的路径（不带 `.md`、不带语言前缀）。
