# 教学与全链路标准

在重写指南、解释 API 或审查源码链路时使用。读者应能回答“从哪里开始读、每一步为什么发生、数据去了哪里、结果如何回到页面”，并沿具体函数自行验证。

## 选择合适的讲解粒度

先用一个可识别的实际操作建立全貌，再深入关键分支。首次出现的概念用项目中的具体对象解释，不假定读者理解 HTTP、事务、队列、轮询或幂等。将零基础操作教程、架构讲解和逐 API 深入阅读分层连接，避免一个页面承载全部内容。

同一类接口的公共认证、调度和持久化可以共享讲解，但每个实际公开 API 都有自己的可定位章节，写明该接口如何使用公共机制及有何不同。外部回调、管理接口和后台任务以真实调用方起步，不虚构前端按钮。不存在的异步环节不强加 worker 或 Redis。

## 完整追踪一条链路

按实际执行顺序回答以下问题，只展开确实参与的环节。对架构核心流程写清关键分支，而非只有成功箭头。

| 环节 | 读者必须能对照源码确认的内容 |
| --- | --- |
| 触发与前端入口 | 用户在哪个页面点什么，事件绑定、store/composable、API client 分别在哪里；外部系统如何发起回调 |
| 请求边界 | HTTP 方法、路径、关键字段、序列化、认证、workspace 等上下文，以及调用方如何处理 HTTP 错误 |
| 后端入口 | FastAPI 注册、依赖注入、handler、实际业务函数；身份、权限和输入校验发生在哪里 |
| 数据与副作用 | 哪些记录被创建/读取/更新，关联键如何传递；SQL 事务提交点、Redis 用途、对象存储中的真实内容与访问方式 |
| 异步执行与外部系统 | 入队或 outbox 到后台消费者的交接点、提交与轮询、供应商请求/回调、恢复与清理；同步接口明确其同步返回边界 |
| 状态、幂等与结算 | 状态由谁推进、重复请求如何识别、重试条件；确有积分/支付时解释预留、扣费、释放及失败补偿 |
| 响应与页面结果 | 返回字段如何映射到前端状态；查询/轮询何时结束、错误如何显示、重新进入页面如何恢复已保存结果 |

用一个贯穿例子追踪关键标识符，例如 user、workspace、asset、公开任务 ID、幂等键和供应商任务 ID。使用示例值，不包含真实令牌、个人资料、支付数据或私有凭据。区别内存状态、持久化记录与展示进度，避免把名字相似的 ID 当作同一对象。

每个重要检查点说明“此时哪些事实已经成立、哪些还没有成立”。例如上传完成、业务请求被接纳、供应商接受任务和结果成功持久化是不同事件；实际关系必须由代码确认。

## 图表与源码阅读表配合

依据阅读问题选择图表：

- **时序图**：谁按什么顺序调用谁，在哪个位置发生进程或外部系统交接。
- **状态图**：合法状态转换、失败、取消、重试与终态的实际推进者。
- **架构/流程图**：模块职责、部署进程与分支决策；区分代码模块和运行服务。
- **ER 图或数据表**：所有权、关联键、结果及输入如何持久化。
- **对照表**：UI、API、供应商的不同约束，角色权限、配置优先级或平台差异。

关键时序图使用编号，紧接源码阅读表。图里的箭头要能对应实际函数调用、任务交接或消息；不要用一条“后端处理”箭头跳过主要业务。

源码阅读表采用以下信息结构，按真实代码填写：

| 图中步骤 | 源码文件与符号（固定版本链接） | 应阅读的分支/数据 | 为什么要有这一步 |
| --- | --- | --- | --- |
| 与图中消息相同的编号 | 前端函数、handler、业务函数或消费者 | 请求字段、校验条件、关键记录和返回值 | 职责、执行边界与失败含义 |

附上足够短、可解释的关键代码或请求/响应示例；不要整段复制源码代替讲解。复杂链路先画总览，再按阶段拆解；图表编号与源码表保持对应，两种语言保持相同事实。

图表使用仓库现有 Mermaid 渲染和查看控件，实际解析每个新增/改动的 fence。注意渲染器对序列消息标点等语法的要求。桌面利用宽度，移动端保留文字可读性并允许缩放/全屏，不靠无限缩小图中文字解决拥挤。

## 操作教程要能复现

每一步给出执行目录、必要前提、可复制命令、预期结果、验证方式和常见失败处理。明确运行的是前端 Mock、本地真实服务、模拟供应商还是线上环境；构建命令与构建产物应来自当前源码和脚本。

需要后端的首次闭环应覆盖权限或权益前提、输入上传、请求提交、执行完成、结果持久化及前端读取。仅打开页面或收到任务 ID 不代表闭环成功；如果本次没有实际运行应用，应标记验证范围和待执行步骤。

## 审查是否达到 deep dive

对每条变更链路，审查者沿图逐步打开固定版本的实现，并检查：

1. 从真实触发点到结果没有关键跳步，符号存在且调用顺序正确。
2. 关键 ID、权限、事务和持久化位置可追踪；有实际影响的错误/重试分支讲清楚。
3. 当前 UI、API、候选 schema、Mock 和兼容路径的边界有证据，未把计划能力写成已实现。
4. 每个接口从索引可到准确双语章节，共享讲解没有掩盖该接口特有行为。
5. 初学者知道每个源码链接应该读什么、为何阅读；操作说明包含可观察的成功标准。
6. 图、表、代码示例、正文及其他页面使用同一套事实、术语和审计版本。

自动检查只能证明部分结构和来源事实，不能证明这些语义结论。若说明仍只有架构概览、接口字段或文件列表，继续深入实际实现后再交付。
