# Local MinIO and Alibaba OSS Testing

YuanZhu's local smoke and E2E runners always execute the API, PostgreSQL, Redis,
and workers in Docker. The `--storage` switch independently decides where object
bytes live. A **local run** therefore describes where the application compute runs;
it does not necessarily mean every dependency is local.

This page separates the two storage profiles, explains why a local run may contact
an external endpoint, and provides a repeatable environment setup that avoids
mixing deployment and test settings.

## What is real and what is mocked?

| Local runner mode | API / workers | PostgreSQL / Redis | Object storage | WeChat and model provider |
| --- | --- | --- | --- | --- |
| `--storage minio --wechat mock` | Real local containers | Real local containers | Real local MinIO container | Local mock services |
| `--storage oss --wechat mock` | Real local containers | Real local containers | **Real Alibaba OSS over the public endpoint** | Local mock services |
| `--cloud URL` | Existing remote deployment | Remote deployment dependencies | Whatever the remote deployment uses | Whatever the remote deployment uses |

MinIO is not an in-memory function mock. It exercises the S3-compatible signing,
multipart form upload, version ID, ETag, completion, and cleanup paths. It does not
prove Alibaba-specific endpoint, signature, CORS, encryption, or versioning behavior.
That is why storage-boundary changes require a second run against real OSS.

The local voice-upload smoke is narrower than a complete voice-summary user journey.
It proves session creation, fragment exchange, upload intent, direct object upload,
Asset completion, authenticated polling of the resulting `READY` Audio Asset, and
cleanup. It does not submit a design job or call a model provider.

## Three endpoints that are easy to confuse

| Setting or generated value | Purpose | Used for file bytes? |
| --- | --- | --- |
| `CLOUD_API_URL` | Reads prompt, catalog, billing, and legal-document configuration from the test Admin site before a local smoke/E2E run | No |
| `PUBLIC_API_BASE_URL` | Browser-visible address of the local API; generated by `create_stack.sh` from the selected host and port | No |
| `S3_PRESIGN_ENDPOINT` | Browser-reachable object-storage endpoint embedded in signed upload forms | Yes |

The local runners unconditionally import a cloud configuration snapshot into the
disposable local database. This is why a MinIO run still needs internet access to
`CLOUD_API_URL`. Provider credentials are not copied; the local mock provider remains
in use. Object bytes stay in local MinIO.

Running `create_stack.sh` alone does not perform this cloud configuration import.
Running `run_smoke_tests.sh` or local `run_e2e_tests.sh` does.

## Use separate secret files

Keep the original `.env` as the operator/deployment source. Create two ignored,
permission-restricted profiles in the `YuanZhu-AI` repository root:

- `.env.minio-test` for mock-WeChat tests with local MinIO;
- `.env.oss-test` for mock-WeChat tests with real Alibaba OSS.

Set mode `0600` and never commit either file:

```bash
chmod 600 .env.minio-test .env.oss-test
```

Both profiles should contain only these groups copied from the working `.env`:

| Group | Variables |
| --- | --- |
| Local identity and encryption | `ENVIRONMENT`, `APP_VERSION`, `JWT_SECRET`, `ADMIN_SESSION_SECRET`, `CONFIG_ENCRYPTION_KEY`, `ADMIN_SESSION_HTTPS_ONLY`, `ADMIN_PHONE`, `ADMIN_PASSWORD`, `ADMIN_DISPLAY_NAME` |
| Stable smoke/E2E behavior | `INITIAL_USER_TOKENS`, `INITIAL_USER_ALLOWED_WORKSPACES`, `INITIAL_GLOBAL_TOKENS`, `SEED_DEMO_BILLING_CATALOG`, `LEGAL_DOCUMENTS_LOCALE`, `LEGAL_DOCUMENTS_REQUIRED`, provider paths/poll limits, and payment timing limits |
| Cloud configuration source | `CLOUD_API_URL`, `CLOUD_ADMIN_USERNAME`, `CLOUD_ADMIN_PASSWORD` |

The OSS profile additionally needs:

```dotenv
S3_BUCKET=<test-bucket>
S3_REGION=<region>
S3_PRESIGN_ENDPOINT=https://s3.oss-<region>.aliyuncs.com
S3_ACCESS_KEY=<test-access-key-id>
S3_SECRET_KEY=<test-access-key-secret>
S3_SIGNATURE_VERSION=s3
S3_SERVER_SIDE_ENCRYPTION=AES256
S3_PRESIGN_SECONDS=3600
```

Do not place these settings in either local profile:

- `DATABASE_URL` or `REDIS_URL`: Compose owns the isolated local services.
- `PUBLIC_API_BASE_URL`: the launcher derives it from the selected port/host.
- `LEGAL_DOCUMENTS_PUBLIC_BASE_URL`: a stale value can bypass the secure local API
  fallback and point tests at an unrelated bucket or MinIO address.
- `S3_ENDPOINT`: for local OSS, the launcher intentionally uses the public
  `S3_PRESIGN_ENDPOINT` for both server I/O and signing because the laptop cannot
  route to a VPC-only endpoint.
- `CLOUD_POSTGRESQL_*`: local tests do not connect directly to the cloud database.
- Real WeChat/payment credentials: these two profiles intentionally use
  `--wechat mock`. Keep real-WeChat testing in a separate secret profile.

For MinIO, do not copy any OSS credential or endpoint. The launcher injects the
container endpoint `http://minio:9000`, a browser-visible derived host port, local
credentials, `s3v4`, and path-style addressing.

## Preflight checks

Choose and record one API port for the development session. Do not reuse another
task's port or Compose project. The commands below use `19092` only as an example:

```bash
export DEV_TEST_PORT=19092
```

Check that both profiles parse without exposing values:

```bash
STACK_SECRET_FILE=.env.minio-test \
  docker compose --env-file .env.minio-test --profile smoke config --quiet

STACK_SECRET_FILE=.env.oss-test \
  docker compose --env-file .env.oss-test --profile smoke config --quiet
```

Before an OSS run, also verify:

- the endpoint is public HTTPS and does not contain `-internal.aliyuncs.com`;
- bucket versioning is enabled;
- the bucket CORS rule allows the exact frontend origin printed by the launcher,
  with `POST`, `GET`, and `HEAD`, exposes `ETag`, `Content-Length`, and
  `x-oss-version-id`, and does not use wildcard origin;
- the test credentials can read, write, version, and delete only the intended test
  namespace;
- server-side encryption is `AES256` when required by the bucket policy.

## Run focused smoke tests

MinIO:

```bash
./scripts/run_smoke_tests.sh \
  --local localhost \
  --port "$DEV_TEST_PORT" \
  --wechat mock \
  --storage minio \
  --secret .env.minio-test \
  -- smoke_tests/test_voice_upload_sessions.py
```

Real Alibaba OSS:

```bash
./scripts/run_smoke_tests.sh \
  --local localhost \
  --port "$DEV_TEST_PORT" \
  --wechat mock \
  --storage oss \
  --secret .env.oss-test \
  -- smoke_tests/test_voice_upload_sessions.py
```

The OSS command is explicit authorization to create and remove temporary objects in
the configured real bucket. The smoke cleanup deletes the exact uploaded version and
its temporary SQL, Redis, and user/workspace records.

## Run E2E gates

Coverage mode against MinIO:

```bash
./scripts/run_e2e_tests.sh \
  --local localhost \
  --port "$DEV_TEST_PORT" \
  --wechat mock \
  --storage minio \
  --secret .env.minio-test \
  --mode coverage
```

For an OSS-boundary change, repeat with `--storage oss --secret .env.oss-test`.
Use the repository's required runner counts and 300-second endurance command from
the System Test Strategy for a final delivery gate; a focused smoke pass is not a
replacement for those gates.

## Failure map

| Symptom | Likely cause | Correction |
| --- | --- | --- |
| Configuration sync fails before test traffic | Missing/incorrect `CLOUD_API_URL` or cloud Admin credentials | Fix the three `CLOUD_*` values; do not add cloud database credentials |
| MinIO upload URL is unreachable | Wrong selected host/port or a stale manually configured endpoint | Let the launcher generate both MinIO endpoints; use `--local localhost` for host-only testing |
| Legal document fetch points at an old bucket/port | `LEGAL_DOCUMENTS_PUBLIC_BASE_URL` leaked into the test profile | Remove it and use the API fallback |
| OSS launcher rejects the endpoint | Internal/VPC-only or non-HTTPS endpoint | Set the public regional `S3_PRESIGN_ENDPOINT` |
| OSS form POST is rejected | Wrong signature mode, CORS, credentials, or bucket policy | Use `S3_SIGNATURE_VERSION=s3`, merge the exact-origin CORS rule, and verify scoped credentials |
| Completion reports changed/missing content | Versioning, ETag exposure, or exact-version access is unavailable | Enable versioning and expose the required response headers |
| Port collision | Another task owns the API or derived MinIO ports | Select a different session port; never silently take over its stack |

## What each successful run proves

- A MinIO pass proves the application-level S3 contract under a reproducible local
  topology.
- An OSS pass proves the same application contract against Alibaba's real endpoint,
  signature, CORS, versioning, metadata, and encryption behavior.
- Neither pass proves production deployment wiring, real WeChat, or a real model
  provider unless those independent modes were explicitly selected.
- `CLOUD_API_URL` participation proves only configuration import; it does not turn a
  MinIO run into a cloud-storage test.
